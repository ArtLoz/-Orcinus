# Сравнение с desktop OrcaSlicer

Проверка уровня G: G-code, который ядро нарезает на телефоне, сравнивается с
G-code официальной desktop-сборки OrcaSlicer того же релиза на тех же моделях и
профилях.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\engine.ps1 -Stage engine -Target orca_engine_slice
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\golden.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\golden.ps1 -Model V,frog_legs
```

Нужны подключённый телефон и Python 3 (только стандартная библиотека). Всё
рабочее лежит в `engine/build/golden`.

## Как устроено

| Сторона | Что запускается |
| --- | --- |
| Эталон | `OrcaSlicer_Windows_V2.4.2_x64_portable.zip` с GitHub. SHA256 закреплён в `scripts/golden.ps1`, тег `v2.4.2` = commit `8500fcdc` из `upstream/orca.lock.json`. Распаковывается в `engine/build/tools`. |
| Телефон | `orca_engine_slice` — консольная обёртка над `orca_engine_adapter`, тем же фасадом, что в APK. Профили и таблицы Orca лежат на устройстве в той же раскладке, что создаёт приложение. |

`scripts/golden/golden.py prepare` готовит входные данные:

- **Профили.** Командная строка desktop не разрешает `inherits`, ей нужны
  полные JSON. Скрипт проходит цепочку наследования системных профилей
  (`scripts/golden/cases.json`) независимо от кода приложения. Приложение
  разрешает её через `PresetBundle`, так что совпадение настроек проверяет обе
  реализации.
- **Модели.** Берутся из `upstream/OrcaSlicer/tests/data` и ставятся так, чтобы
  центр их габарита совпадал с центром стола, а низ лежал на столе.
  - Зачем так: приложение размещает модель как desktop GUI
    (`Plater::priv::load_model_objects`) — центрирует сетку вокруг нуля и ставит
    экземпляр в центр стола. Командная строка так не умеет: без `--arrange 0` она
    расставляет сама (может повернуть на 90° или сдвинуть на 0,001 мм). При
    точном центре оба сдвига приложения взаимно гасятся без округлений, и обе
    стороны режут одинаковые координаты.
  - Модели пишутся текстовым STL с 9 значащими цифрами: так float32 сохраняется
    без потерь. Двоичный STL не подходит: admesh принимает маленький двоичный
    файл возле 175 мм за текстовый, потому что определяет формат по байтам
    больше 127.

`golden.py compare` проверяет каждую пару файлов.

## Критерии

| Проверка | Требование |
| --- | --- |
| Настройки (`CONFIG_BLOCK`) | Совпадают, кроме перечисленных ниже отличий командной строки. |
| Слои | Одинаковое число, одинаковые `Z` и `HEIGHT`, одинаковые типы путей (`;TYPE:`) в каждом слое. |
| Выдавливание печатных движений в слое | Отличается не больше чем на 1 %. |
| Расход филамента | Не больше 0,1 %. |
| Время печати | Не больше 1 %. |

Отличия настроек, которые даёт сама командная строка desktop:

| Параметр | Причина |
| --- | --- |
| `filament_colour`, `extruder_colour` | Командная строка присваивает загруженному пластику свой цвет. |
| `flush_volumes_matrix`, `flush_volumes_vector` | Командная строка заводит таблицу промывки на несколько пластиков. |
| `compatible_printers_condition`, `different_settings_to_system`, `inherits_group` | Есть только в выводе командной строки. |
| 13 ключей хоста печати и вариантов экструдера (`printhost_*`, `bbl_use_printhost`, `extruder_variant_list` и др.) | Есть только у `PresetBundle::full_config()`. |

Появление любого другого различия настроек — ошибка.

## Почему не побайтно

Проверено, что обе стороны детерминированы: три запуска подряд дают один и тот
же файл и на телефоне, и на ПК. Отличия между ними платформенные.

1. **Математическая библиотека.** Windows (UCRT) и Android (bionic) расходятся в
   последнем бите на одинаковых входах. 20 000 случайных аргументов:

   | Функция | Доля расхождений |
   | --- | --- |
   | `atan2` | 23 % |
   | `tan` | 3,9 % |
   | `asin` | 2,5 % |
   | `sin`, `cos` | 1,8 %, 1,6 % |
   | `acos`, `exp` | 0,9 %, 0,6 % |
   | `sqrt` | 0 (IEEE 754 требует точного округления) |

   Эти функции участвуют в повороте заливки, аппроксимации дуг и расчёте углов.
   Смещение на единицу последнего бита иногда меняет пороговые решения:
   появляется или пропадает отрезок длиной в сотые доли миллиметра. Отключение
   аппроксимации дуг картину не меняет. Desktop OrcaSlicer под Windows и под
   Linux/macOS расходится так же.
2. **Равноценные варианты.** В симметричной геометрии зигзаг заливки начинается
   с другого угла, очистка сопла идёт вдоль другой стороны. Отрезки те же, длина
   и выдавливание те же.
3. **Следствия.** Другой обход меняет время слоя, от него — замедление для
   охлаждения (`F8663` вместо `F8653`) и место строк прогресса `M73`.

## Что сравнение не покрывает

- **Расстановку на столе.** Приложение повторяет код `Plater::priv::load_model_objects`,
  но командная строка desktop этот путь не проходит; в сравнении расстановка
  нейтрализована подготовкой моделей.
- **Поведение GUI сверх нарезки:** цвет пластика, миниатюры в G-code (desktop рисует
  их через OpenGL), несколько объектов и столов.
- **Другие профили и режимы:** поддержки (в выбранном профиле выключены), другие
  принтеры и пластики.

## Обновление OrcaSlicer

После обновления submodule `scripts/golden.ps1` откажется запускаться, пока в нём
не заменены `$referenceRelease`, `$referenceUrl` и `$referenceSha256` на
Windows x64 portable-архив нового релиза (SHA256 есть в описании ассета на
GitHub). Если изменились ключи конфигурации, сравнение покажет их явно; списки
допустимых отличий — в `scripts/golden/golden.py`.
